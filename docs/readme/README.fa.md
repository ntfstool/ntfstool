# NTFSTool (نسخهٔ متن‌باز)

NTFS رایگان و متن‌باز با قابلیت خواندن و نوشتن برای macOS، ساخته‌شده بر پایهٔ
**FSKit** اپل و موتور NTFS اختصاصی NTFSTool (**libntfstool-driver**).

یک درایو ویندوزی (NTFS) را وصل کنید تا macOS آن را از طریق ماژول درایور FSKit مربوط به NTFSTool با قابلیت نوشتن سوار کند — بدون افزونهٔ هسته
(kernel extension)، بدون macFUSE، بدون کاهش تنظیمات امنیتی و بدون رمز عبور مدیر. خود برنامه کاملاً در جعبهٔ شن (sandbox) اجرا می‌شود.

## تصاویر صفحه

تصاویر واقعی از برنامه‌ای که از همین مخزن ساخته شده است (`make app`). درایوهای نمایش‌داده‌شده درایوهای نمونهٔ
حالت نمایشی داخلی (`make demo`) هستند، بنابراین می‌توانید همهٔ صفحه‌ها را بدون دیسک فیزیکی امتحان کنید.

### راه‌اندازی هدایت‌شده: بدون رمز عبور، بدون افزونهٔ هسته

NTFSTool یک ماژول معمولی سیستم فایل FSKit است. تنها چیزی که macOS می‌خواهد یک کلید در
**تنظیمات سیستم ← عمومی ← ورودها و افزونه‌ها ← افزونه‌های سیستم فایل** است. برنامه آن را گام‌به‌گام
توضیح می‌دهد و تغییر را خودش تشخیص می‌دهد.

## این مخزن چیست

این **نسخهٔ متن‌باز آموزشی / مرجع** NTFSTool است. از NTFSTool رایگان در Mac App Store مشتق شده و همان معماری را حفظ می‌کند، اما عمداً کوچک و خوانا نگه داشته شده است:

- هر فایل منبع به انگلیسی توضیح‌نویسی شده است، تا بتوانید بررسی کنید که یک ماژول سیستم فایل FSKit، یک پل C روی
  موتور NTFS، و یک رابط SwiftUI/AppKit در جعبهٔ شن چگونه کنار هم قرار می‌گیرند؛
- درایور از مسیر ساده و مستقیم ورودی/خروجی استفاده می‌کند (بدون لایهٔ کش و بدون بهینه‌سازی عملکرد مخصوص پلتفرم)؛
- برنامه فقط کارهای پایه را انجام می‌دهد (بدون تله‌متری، بدون ارسال عیب‌یابی، و اصلاً بدون دسترسی به شبکه)؛
- هیچ کدی برای مجوزدهی، فعال‌سازی یا دورهٔ آزمایشی وجود ندارد.

اگر فقط به‌عنوان کاربر بهترین تجربه را می‌خواهید، نسخه‌های رسمی را از [ntfstool.com](https://ntfstool.com) نصب کنید.
NTFSTool Pro (متن‌بسته) یک درایور دوم برای نسخه‌های قدیمی‌تر macOS، تعمیر دیسک و ابزارهای دیگر اضافه می‌کند.

## ویژگی‌ها

- خواندن **و نوشتن** حجم‌های NTFS؛ macOS آن‌ها را به‌طور خودکار از طریق ماژول درایور FSKit سوار می‌کند
- برنامهٔ داخل جعبهٔ شن؛ درایور به‌صورت ماژول FSKit در جعبهٔ شن و در فضای کاربر اجرا می‌شود
- وضعیت هر حجم NTFS را نشان می‌دهد: خواندن و نوشتن، فقط‌خواندنی (ویندوز در خواب زمستانی / راه‌اندازی سریع)، فقط‌خواندنی
  توسط درایور داخلی اپل، سوار نشده
- شما را برای روشن کردن افزونهٔ سیستم فایل در تنظیمات سیستم راهنمایی می‌کند
- باز کردن در Finder، بیرون دادن، اطلاعات دیسک
- ۲۰ زبان رابط کاربری
- ویژگی‌های گسترده (extended attributes) به‌صورت جریان‌های نام‌دار NTFS ذخیره می‌شوند (بدون فایل‌های `._`)؛ گزینهٔ اختیاری سوار کردن `windows_names`
  نام فایل‌هایی را که ویندوز نمی‌تواند استفاده کند رد می‌کند

## نیازمندی‌ها

- برای اجرا macOS 15.6 یا جدیدتر؛ **پشتیبانی از نوشتن به macOS 26 یا جدیدتر نیاز دارد** (در macOS 15 سیستم برای دیسک‌های فیزیکی
  همچنان از درایور NTFS فقط‌خواندنی اپل استفاده می‌کند)
- برای ساخت: Xcode 16.3 یا جدیدتر (FSKit SDK) همراه با ابزارهای خط فرمان آن، Swift 5.9+

## ساخت — با یک دستور

```sh
git clone https://github.com/ntfstool/ntfstool.git
cd ntfstool
make            # → build/NTFSTool.app (ad-hoc signed, native architecture)
```

هدف‌های دیگر:

| دستور | کاری که انجام می‌دهد |
| --- | --- |
| `make run` | برنامه را می‌سازد و باز می‌کند |
| `make demo` | رابط کاربری را با دیسک‌های نمایشی در حافظه اجرا می‌کند — بدون درایور و بدون حساب Apple Developer |
| `make test` | آزمون‌های واحد را اجرا می‌کند |
| `make app UNIVERSAL=1` | arm64 + x86_64 می‌سازد |
| `make scan` | بررسی می‌کند که هیچ مواد امضا یا شناسهٔ خصوصی در درخت پروژه نباشد |

آزمون‌های درایور، تصاویر دیسک واقعی NTFS را با زیردستورهای `mkntfs` و `ntfsfix` فایل اجرایی `ntfstool-driver` قالب‌بندی و بررسی می‌کنند. اگر هر دو ابزار در
`bin`/`sbin` مربوط به Homebrew یا در پوشه‌ای که با `NTFSTOOL_NTFS_TOOLS=<dir>` مشخص شده یافت نشوند، این آزمون‌ها رد می‌شوند.

## اجرای درایور (به حساب Apple Developer خودتان نیاز دارد)

ماژول FSKit از امتیاز (entitlement) محدودشدهٔ `com.apple.developer.fskit.fsmodule` استفاده می‌کند. macOS فقط ماژولی را بارگذاری می‌کند
که امضای آن با یک provisioning profile پشتیبانی شود که این امتیاز را می‌دهد. ساخت ad-hoc کل رابط کاربری را نشان می‌دهد، اما
سیستم درایور را بارگذاری نمی‌کند. این یک قاعدهٔ پلتفرم اپل است که برای هر پروژهٔ FSKit اعمال می‌شود.

1. در حساب Apple Developer خود دو App ID بسازید، مثلاً `com.yourname.ntfs` و `com.yourname.ntfs.fskit`.
   قابلیت **FSKit Module** را روی دومی فعال کنید، و در صورت تمایل یک App Group
   (مثلاً `TEAMID.com.yourname.ntfs`) روی هر دو تا برنامه بتواند گزارش درایور را بخواند.
2. برای هر دو provisioning profile توسعه (یا Developer ID) بسازید و دانلود کنید.
3. با هویت خود بسازید:

   ```sh
   TEAM_ID=ABCDE12345 \
   BUNDLE_ID=com.yourname.ntfs \
   SIGN_IDENTITY="Apple Development: Your Name (XXXXXXXXXX)" \
   APP_PROFILE=~/Downloads/app.provisionprofile \
   FSKIT_PROFILE=~/Downloads/fskit.provisionprofile \
   make app
   ```

4. `build/NTFSTool.app` را در `/Applications` کپی کنید، یک بار آن را باز کنید، سپس درایور را در
   **تنظیمات سیستم ← عمومی ← ورودها و افزونه‌ها ← افزونه‌های سیستم فایل** روشن کنید.
5. درایو NTFS را دوباره وصل کنید. اکنون `mount` باید آن را با نوع `ntfstooloss` فهرست کند.

همهٔ گزینه‌های ساخت در ابتدای [`scripts/build-app.sh`](../../scripts/build-app.sh) مستند شده‌اند.
provisioning profileها و کلیدهای امضا هرگز نباید در این مخزن باشند؛ `make scan` این را بررسی می‌کند.

## ساختار

| مسیر | چیست |
| --- | --- |
| `Sources/NTFSTool` | نقطهٔ ورود برنامه (`main.swift`) |
| `Sources/NTFSToolApp` | پوستهٔ AppKit، نماهای SwiftUI، مدل برنامه، سرویس‌های سیستمی، ۲۰ بومی‌سازی |
| `Sources/NTFSToolCore` | منطق خالص بدون AppKit: مدل دیسک، فهرست زبان‌ها، ذخیرهٔ تنظیمات، گزارش رویداد محلی |
| `Sources/NTFSToolBridge` | پل C (`ntfstool_bridge.c`) که عملیات مبتنی بر inode را روی `libntfstool-driver` ارائه می‌دهد |
| `Sources/NTFSToolDriver` | هستهٔ Swift درایور (بدون وابستگی به FSKit، قابل آزمون واحد روی هر macOS) |
| `FSKitModule/NTFSToolFS` | ماژول FSKit (`NTFSToolFS.appex`) که macOS برای سوار کردن حجم‌های NTFS بارگذاری می‌کند |
| `Tests/` | آزمون‌های واحد برای مدل برنامه و درایور (با تصاویر واقعی NTFS) |
| `scripts/` | `build-app.sh`، `build-fskit.sh`، `scan-secrets.sh` |

برای دیدن اینکه یک نوشتن چگونه از Finder تا دیسک می‌رود، [docs/ARCHITECTURE.md](../ARCHITECTURE.md) را ببینید.
