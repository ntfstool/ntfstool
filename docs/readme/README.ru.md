# NTFSTool (версия с открытым исходным кодом)

Бесплатная NTFS с чтением и записью для macOS с открытым исходным кодом, построенная на **FSKit** от Apple и собственном NTFS-движке
NTFSTool (**libntfstool-driver**).

Подключите диск Windows (NTFS), и macOS смонтирует его с возможностью записи через модуль драйвера FSKit от NTFSTool — без расширений ядра,
без macFUSE, без снижения настроек безопасности, без пароля администратора. Само приложение работает полностью в песочнице.

### Пошаговая настройка: без пароля и без расширения ядра

NTFSTool — это обычный модуль файловой системы FSKit. Единственное, что требует macOS, — включить один переключатель в **Системные настройки

## Что это за репозиторий

Это **учебная и справочная версия NTFSTool с открытым исходным кодом**. Она происходит от бесплатного NTFSTool из Mac App Store и сохраняет
ту же архитектуру, но намеренно сделана небольшой и читаемой:

- каждый исходный файл прокомментирован на английском, так что вы можете изучить, как сочетаются модуль файловой системы FSKit, C-мост
  поверх NTFS-движка и работающий в песочнице интерфейс на SwiftUI/AppKit;
- драйвер использует простой прямой путь ввода-вывода (без слоя кэширования и без оптимизаций производительности под конкретную платформу);
- приложение умеет только самое необходимое (без телеметрии, без отправки диагностики, вообще без доступа к сети);
- в нём нет кода лицензирования, активации или пробного периода.

Если вам просто нужен наилучший опыт использования, установите официальные сборки с
[ntfstool.com](https://ntfstool.com). NTFSTool Pro (с закрытым исходным кодом) добавляет второй драйвер для более старых версий macOS,
восстановление дисков и другие инструменты.

## Возможности

- Чтение **и запись** томов NTFS; macOS монтирует их автоматически через модуль драйвера FSKit
- Приложение работает в песочнице; драйвер работает как модуль FSKit в песочнице в пользовательском пространстве
- Показывает состояние каждого тома NTFS: чтение и запись, только чтение (Windows в гибернации / быстрый запуск), только чтение через
  встроенный драйвер Apple, не смонтирован
- Помогает включить расширение файловой системы в Системных настройках
- Открытие в Finder, извлечение, сведения о диске
- 20 языков интерфейса
- Расширенные атрибуты хранятся как именованные потоки NTFS (без файлов `._`); необязательная опция монтирования `windows_names` отклоняет
  имена файлов, которые не может использовать Windows

## Требования

- macOS 15.6 или новее для запуска; **для записи нужна macOS 26 или новее** (в macOS 15 система продолжает использовать для физических
  дисков встроенный драйвер NTFS Apple, работающий только на чтение)
- Для сборки: Xcode 16.3 или новее (SDK FSKit) с инструментами командной строки, Swift 5.9+

## Сборка — одной командой

```sh
git clone https://github.com/ntfstool/ntfstool.git
cd ntfstool
make            # → build/NTFSTool.app (ad-hoc signed, native architecture)
```

Другие цели:

| Команда | Что делает |
| --- | --- |
| `make run` | собирает и открывает приложение |
| `make demo` | запускает интерфейс с демонстрационными дисками в памяти — драйвер и аккаунт Apple Developer не нужны |
| `make test` | запускает модульные тесты |
| `make app UNIVERSAL=1` | собирает arm64 + x86_64 |
| `make scan` | проверяет, что в дереве нет материалов для подписи и закрытых идентификаторов |

Тесты драйвера форматируют и проверяют настоящие образы дисков NTFS с помощью подкоманд `mkntfs` и `ntfsfix` бинарного файла
`ntfstool-driver`. Они пропускаются, если оба инструмента не найдены в `bin`/`sbin` Homebrew или в каталоге, заданном через
`NTFSTOOL_NTFS_TOOLS=<dir>`.

## Запуск драйвера (нужен собственный аккаунт Apple Developer)

Модуль FSKit использует ограниченное право `com.apple.developer.fskit.fsmodule`. macOS загружает только тот модуль, подпись которого
подкреплена профилем предоставления (provisioning profile), выдающим это право. Ad-hoc-сборка показывает весь интерфейс, но система не
загрузит драйвер. Это правило платформы Apple, действующее для любого проекта на FSKit.

1. В своём аккаунте Apple Developer создайте два App ID, например `com.yourname.ntfs` и `com.yourname.ntfs.fskit`. Включите для второго
   возможность **FSKit Module** и, по желанию, App Group (например, `TEAMID.com.yourname.ntfs`) для обоих, чтобы приложение могло читать
   журнал драйвера.
2. Создайте для обоих профили предоставления для разработки (или Developer ID) и скачайте их.
3. Соберите проект со своей подписью:

   ```sh
   TEAM_ID=ABCDE12345 \
   BUNDLE_ID=com.yourname.ntfs \
   SIGN_IDENTITY="Apple Development: Your Name (XXXXXXXXXX)" \
   APP_PROFILE=~/Downloads/app.provisionprofile \
   FSKIT_PROFILE=~/Downloads/fskit.provisionprofile \
   make app
   ```

4. Скопируйте `build/NTFSTool.app` в `/Applications`, один раз откройте его, затем включите драйвер в **Системные настройки → Основные →
   Объекты входа и расширения → Расширения файловых систем**.
5. Подключите NTFS-диск заново. Теперь `mount` должен показать его с типом `ntfstooloss`.

Все параметры сборки описаны в начале файла [`scripts/build-app.sh`](../../scripts/build-app.sh). Профили предоставления и ключи подписи не должны
попадать в этот репозиторий; `make scan` это проверяет.

## Структура

| Путь | Что это |
| --- | --- |
| `Sources/NTFSTool` | Точка входа приложения (`main.swift`) |
| `Sources/NTFSToolApp` | Оболочка AppKit, представления SwiftUI, модель приложения, системные службы, 20 локализаций |
| `Sources/NTFSToolCore` | Чистая логика без AppKit: модель диска, список языков, хранилище настроек, локальный журнал событий |
| `Sources/NTFSToolBridge` | C-мост (`ntfstool_bridge.c`), предоставляющий операции на основе inode поверх `libntfstool-driver` |
| `Sources/NTFSToolDriver` | Swift-ядро драйвера (без зависимости от FSKit, тестируется модульными тестами на любой macOS) |
| `FSKitModule/NTFSToolFS` | Модуль FSKit (`NTFSToolFS.appex`), который macOS загружает для монтирования томов NTFS |
| `Tests/` | Модульные тесты модели приложения и драйвера (на настоящих образах NTFS) |
| `scripts/` | `build-app.sh`, `build-fskit.sh`, `scan-secrets.sh` |

О том, как запись проходит путь от Finder до диска, читайте в [docs/ARCHITECTURE.md](../ARCHITECTURE.md).
